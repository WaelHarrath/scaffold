# SCAFFOLD — Reproducibility

**Status:** RESEARCH FREEZE — consolidation
**Date:** 2026-08-28

This document describes how to reproduce the SCAFFOLD benchmark results. It records the frozen environment, the measured invariant checks, and the known reproducibility boundaries.

> **Important:** Do **NOT** use results from the historical v1 archive (`scaffold-v1-history`, which used `qwen2.5:1.5b` / `qwen2.5:3b`) as evidence for the current Qwen3-4B system. Only results measured with the frozen configuration (`qwen3:4b-instruct` + `all-minilm:latest`) apply to this system.

## 2. Reproduction Commands

Phase runners and report writers use the `phase<k>` npm scripts. Executing a benchmark requires a running Ollama with the frozen models present:

```bash
npm run phase1   # 400 execs, 4 conditions
npm run phase2   # 400 execs, 4 conditions (post executor fix)
npm run phase3   # 1000 execs, 10 conditions
npm run phase4   # 800 execs, 8 conditions
npm run phase6   # 1000 execs, 10 conditions (compression)
npm run phase7   # 400 execs, FULL vs RETRIEVAL_75 (paired)
npm run phase8   # 200 execs, RETRIEVAL_75 vs ADAPTIVE_HYBRID (parity)
```

Phase 5 was analysis-only (no runner). Results land in `benchmarks/results/phase<k>/` (results.json + checkpoint.json); reports are generated by `scripts/write-phase<k>-report.ts` into `benchmarks/PHASE<k>-REPORT.md`.

## 5. Known Reproducibility Boundaries

1. **Stochastic model output.** `qwen3:4b-instruct` has no seed support via the adapter → exact success counts vary across runs; expect variance roughly within the Phase 7 CI [-1.7%, +2.7%] for equal configurations.
2. **Estimator-based token counts.** Prompt/completion tokens come from Ollama (`prompt_eval_count`/`eval_count`); feedback and retrieval token counts are `ceil(len/4)` estimates, not exact model tokenizations.
3. **Embedding cache size.** Benchmark runs use `new EmbeddingCache(500)`; workspaces larger than the cache re-embed repeatedly, which affects runtime (embedding cost is tracked separately from model-call latency). This does not change success outcomes.
4. **Hardware dependence.** Absolute latency/throughput figures are machine-specific.
5. **Historical-model confusion.** Old-model numbers must never be cited as evidence for the current system (see note above).

## 6. Making the Results Reproducible in Practice

- Keep the frozen model tags pinned (`qwen3:4b-instruct`, `all-minilm:latest`).
- Run the verification gate before and after any benchmark to confirm infrastructure invariants.
- Record the Ollama version and machine specs alongside runs for latency comparability.
- Treat small percentage-point deltas (≤ ~3pp) between near-equal configurations as within noise unless a paired contrast (McNemar) supports a difference.
